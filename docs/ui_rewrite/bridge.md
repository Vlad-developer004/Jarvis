# UI bridge: live data from the core to the new window

Always on: `main.py` starts the bridge and the window process (`ui_next/shell.py`) at startup. `JARVIS_NO_WINDOW=1` starts the core without the window.

## How it works
- `ui_next/bridge/hub.py`: a loopback HTTP server (stdlib only) that streams Server-Sent Events on `GET /events?token=...`. A random token, `Host` and `Origin` checks protect it from web pages and other hosts. New clients receive the last value of every sticky topic first.
- `ui_next/bridge/observer.py`: a thread that polls state the core already keeps (HUD state, `app_state.game_mode`, `app_state.mic_level`, HUD notices) and a weather loop (`get_weather_hud`, every 10 min). It publishes changes only.
- Hooks in the core (all wrapped in try/except, no-ops without the bridge): `recognition.handle_recognized_text` -> `bridge.heard`, `TTSManager.speak` -> `bridge.reply`. The bridge pairs them into history rows (streamed answer chunks within 8 s merge into one row).
- `main.py` starts the bridge after the engine is ready when the env flag is set; it writes `%APPDATA%\Jarvis\ui_bridge.json` ({port, token, pid}), removed on exit.
- The Tauri shell reads that file through the `bridge_info` command; `shared.js` connects with `EventSource` and re-reads the file after a disconnect (core restart).

| topic | payload | sticky |
|---|---|---|
| `state` | `{mode: IDLE/LISTENING/SPEAKING/LOADING}` | yes |
| `lang` | `{language: ru/uk}` the core's interface language, sent when the window connects and whenever it changes (also from the old window or a voice command); the window follows it, see appearance.md | yes |
| `perf` | one System-screen sample, see the `perf` command | no |
| `game` | `{on, profile}` | yes |
| `notices` | `[{id, text, sev: info/warn/err}]` | yes |
| `history` | `[{said, did, ts}]` (last 12) | yes |
| `weather` | `{ok, city, temp, feels, desc, code, sunrise, sunset, wind, humidity, pressure}` | yes |
| `timers` | `{timer: {label, remaining, total} or null, reminders: [{id, text, at}]}` (timer from `actions.game_timer`, reminders from the `features.reminder.pending_items()` registry) | yes |
| `muted` | `{on}` (`app_state.ignore_mode`, the old reactor-click mute) | yes |
| `mic` | `{gain, threshold}` from `core.mic_calibration.load_profile()` | yes |
| `speech` | `{ts}` last voice onset, ms | yes |
| `autostart` | `{on}` Windows autostart | yes |
| `library` | `{games: [{id, name, launcher, last, icon}], scanning}`: installed games from `features.gaming.scanner` (Steam, Epic, Xbox), scanned in a thread at start and on the `library` command, most recently played first; `icon` is a 64 px PNG data URI of the game exe (`bridge/gameicons.py`), empty when none is found | yes |
| `songs` | `{songs: [{id, title, artist, album, at, source, cover, links}], total}`: recognized songs from `actions/song_cache.py` (last 100, newest first); `cover` is a 112 px JPEG data URI or empty (the cached cover files live in %TEMP%), `links` lists the services that have a link; republished when the history file changes (`bridge/songs.py`) | yes |
| `voice_cal` | `{state: running\|done\|error, text, threshold?, gain?}`: progress of the microphone calibration | yes |
| `voice_llm` | `{custom, default_present, busy: ''/picking/validating/downloading, pct, text}`: state of the local model (file check, download progress) | yes |
| `extensions` | `[{id, name, desc, type, category, installed, bundled, commands, simple}]` from `core.extensions.ExtensionManager`; re-read when `extensions_installed.json` changes | yes |
| `catalog` | `{categories, games, ext, items, starters}` built once at start by `ui_next/bridge/catalog.py`. General items (`mode` run/confirm/voice, plus `try`, optional `needs` = extension id) come from `COMMAND_PATTERNS`/`CANON_SIMPLE` and `commands_meta.META`; game items (`mode: game`, `cat: game:<profile>`, `more` = extra variants) come from the user's `game_profiles/*.json` (ru or uk). `ext` says whether the needed extensions are installed. | yes |
| `heard`, `reply` | `{text, ts}` | no |
| `level` | `{v: 0..1}` (mic RMS, sqrt-scaled) | no |

## Commands (UI -> core), `POST /cmd?token=...` with a JSON body `{cmd, ...}`
Only whitelisted commands run; any other name is a 404, a bad token/Origin/Host is a 403. The whitelist is `run_command` in `ui_next/bridge/__init__.py`: `COMMANDS` (handlers that use the package's own state: run, timer, reminder, mic, game launch, dialogs), `_ROUTES` (operation routers in `routes.py`, which read the package state at call time) and `_SCREENS` (a screen module with its own `run(data)`, imported on first use). A new command is one entry in one of the three; keep `__init__.py` under the 600-line limit.

| cmd | body | effect |
|---|---|---|
| `autostart` | `{on}` | `core.system.autostart_set` |
| `mic` | `{on}` | sets `app_state.ignore_mode = not on` under the state lock (microphone on/off) |
| `timer` | `{op: start, seconds, label?}`, `{op: add, seconds}`, `{op: cancel}` | `actions.game_timer` (start replaces a running timer, like the voice command); seconds 1..86400 |
| `reminder` | `{op: add, seconds, text}`, `{op: cancel, id}` | `features.reminder.schedule_reminder` / `cancel_reminder` (new: cancel event per reminder); text up to 120 chars |
| `game_launch` | `{id}` (an id from `library`, never a name or path) | `handler._launch_game_engine`, the same path as the voice command (game mode on, profile applied) |
| `library` | `{}` | rescans the installed games |
| `song_open` | `{id, service}` (`spotify`, `apple`, `youtube`) | opens the stored link in the default browser; app-scheme links are turned into https search URLs, other schemes are refused |
| `song_clear` | `{}` | clears the recognized-songs history |
| `ext_setup` | `{id, op: get\|save\|act, ...}` for guard camera, mail, calendar, ETS2, Planetbase (`bridge/ext_setup.py`) | `get` returns the form state (never a secret: only `has_password`); `save` applies the form (Telegram chat id, mail account, calendar sources) and installs the extension; `act` runs `install` (ETS2 plugin, Planetbase mod; background thread), `ai` (ETS2 narrator), `app_password_page`, `uninstall`. Uses the old dialog's helpers, so both UIs share `jarvis_settings.json` and `secrets.env`. If the ETS2 game folder is unknown the reply has `needs_path`: picking it still happens in the old dialog |
| `profile` | `{op, game, ...}`: `games`, `get`, `set_key`, `test`, `macro_get`, `macro_save`, `macro_create`, `macro_delete`, `grid_set` (`bridge/profiles.py`) | game profile editor: key bindings, macros (game actions, keys, pauses) and Hogwarts F1-F4 spell slots. Edits the JSON files in `actions.game_input.PROFILES_DIR` with the old editors' rules (a real key replaces a spell's macro, a macro is deleted by name) and reloads the profile when it is the active game. Keys come from `KeyboardEvent.code`, validated again in the core; `test` presses the keys, so the game window must be in front |
| `currency` | `{op: get}`, `{op: set, base}`, `{op: watch, codes}`, `{op: rates}` | exchange-rate settings in jarvis_settings.json: `currency_base` (home currency, default UAH) and `currency_watch` (followed currencies, default USD and EUR, up to 12). `get` returns `{base, list, watch}`, `rates` prices the followed ones now. By voice: "курс юаня" (in the home currency), "курс юаня к лире" (named pair), "мои курсы" (all followed). 34 currencies plus bitcoin, names in `actions/currency_data.py`, logic in `actions/currency_pairs.py` |
| `voice` | `{op: get}`, `{op: set, key, value}`, `{op: devices}`, `{op: set_devices, input, output}`, `{op: calibrate}`, `{op: say}`, `{op: llm, do: state|pick|reset|download|cancel}` (`bridge/voice.py`) | Voice screen: speech engine, mic threshold / gain (applied live), input and output devices, headphone mode, calibration, volume, speed, night mode, wake mode and timeout, form of address, local-model switch and its model file (picked in a native dialog, test-loaded in a throwaway process before it is stored, or the default ~870 MB download with progress), interface language (`language`; speech stays pinned to Russian). Every key is validated and applied like the old settings tab; values are written through `core/settings_io.py`, which also updates the HUD's in-memory copy so the old HUD does not overwrite them later. Calibration runs in a thread and reports on the `voice_cal` topic |
| `mail` | `{op: state\|folders\|list\|read\|flag\|remove\|save\|reveal\|send\|pick\|drop, ...}` (`bridge/mail.py`, `imapsession.py`, `mail_render.py`) | Mail screen. One long-lived IMAP connection (reconnects itself), folders found by special-use flags (inbox, sent, drafts, junk, trash, archive), the first page of a folder and the last 10 opened letters cached in memory, a background warm-up at start; `list {folder, filter: all\|unread\|flagged, q, offset, refresh}` pages 40 at a time and searches on the server (UTF-8 TEXT); `read {folder, uid, images, mark}` returns the plain text plus a sanitized HTML document for a sandboxed frame (scripts, frames, forms, event attributes dropped; links only through `data-url` and `open_url`; remote images blocked until `images: true`; inline cid images embedded), recipients, attachment names and marks the letter read unless `mark: false`; `flag {flag: seen\|flagged, on}`; `remove {to: ''\|trash\|archive}` moves to the folder or deletes for good; `save {idx}` writes a received attachment to Downloads under a safe name, `reveal` shows only files saved that way; `send {..., quote: {folder, uid, mode: reply\|fwd}}` builds the outgoing message with the original letter: quoted text plus a formatted HTML alternative (sanitized fragment, real links), or appended under a forward; `pick`, `drop` as before (attachments by registered ids only). Also: custom folders and labels (`folders` returns `custom: [{id: f1, name}]`, addressed by id, never by raw name); Gmail-style search in `q` (`from:` `to:` `cc:` `subject:` `is:unread|read|starred` `has:attachment` `after:` `before:`, the rest is a TEXT search); `flag` and `remove` take `uids` (up to 200) and `remove.to` may be `trash|archive|junk|<folder id>`; `read_all {folder}`, `empty {folder}` (trash and junk only); `prefs` / `prefs_set {signature}` (the signature is appended to every sent message unless `sign: false`); `draft {to, cc, bcc, subject, body, attach, replace}` stores a draft in Drafts (`replace` removes the draft being edited; `send` takes the same field). The screen keeps removals for 6 s so the user can undo them before they are written to the server. Rich text: `send` and `draft` also take `html` (what the editor produced); it is sanitized into a fragment (real links, no scripts, frames, forms or <style>) and sent as the HTML alternative next to the plain `body`. `unsubscribe {folder, uid}` leaves a mailing list using the letter's own List-Unsubscribe headers (the UI only gets `unsub: {kind: oneclick|web|mail, target}` from `read`, never the link): RFC 8058 one-click POST to public https hosts only (no redirects, 10 s), the web page in the browser (http/https), or a mail with the address from `mailto:`. |
| `calendar` | `{op: state\|events\|search\|add\|update\|delete\|add_source\|import_file\|remove_source\|source_set\|remind\|refresh, ...}` (`bridge/calendar.py` over `actions/calendar_hub.py`) | Calendar screen. `events {from, to}` (up to 100 days) returns one list from every visible source and the user's own events: title, date and time, end date and time, all-day flag, place, notes, source name and colour, and for own events the repeat rule, `remind` and the `series` start. Own events (`add` / `update`: title, date, time, end_date, end_time, all_day, repeat daily|weekly|monthly|yearly, interval, weekdays, until, location, notes, color `#rrggbb`, remind `null` (default) | `[]` (none) | minutes list) live in `local_events.json`; `delete {eid, only_date}` removes a series or one day of it. `search {q}` looks a year back and ahead. Sources keep name, colour and a hidden flag (`source_set`); `import_file` copies a picked .ics next to the settings. The same hub feeds the voice command, the morning briefing and the spoken reminders (lead time from the settings, or the event's own list), downloads are cached for 5 minutes and a failed refresh serves the last good copy (shown as stale). Also: `update_one {eid, occ, ...fields}` changes or moves one occurrence of a repeating own event (stored as `overrides`, exported with RECURRENCE-ID; `reset_one` undoes it; every occurrence carries `occ`, its date in the series, and `changed`); `quick {text, date}` parses a phrase (`actions/calendar_quick.py`, the same parser as the voice command "добавь в календарь ..." which stores an own event and says what it did); CalDAV calendars (`actions/caldav_client.py`: Yandex, iCloud, Fastmail, Nextcloud, any server with a login and an app password): `caldav_find {server, user, password}` lists the calendars, `caldav_add {..., calendars}` connects them (the password goes to the secrets file as JARVIS_CALDAV_PASS_<id>, never to the settings or back to the screen); their events come with `src`, `href`, `etag` and `rw` (false for recurring ones, which stay read-only); `add {calendar: <source id>}`, `update {src, href, ...}` and `delete {src, href}` write to the server (hrefs must lie inside the connected calendar, a stale etag gives `changed`). Google and Outlook stay read-only through their .ics link: writing needs their OAuth. |
| `open_url` | `{url}` | opens an http(s) link from a letter in the default browser; other schemes, spaces and control characters are refused |
| `tools` | `{op: state\|max_videos\|video_del\|meeting_add\|meeting_edit\|meeting_del\|video_meta\|keep_add\|keep_del\|launch_set\|launch_del\|apps\|remote_save\|remote_off\|auto_update\|update_check\|update_install, ...}` | Settings > Tools (`ui_next/bridge/tools.py`, screen `tools.js`). Same storage as the old window: `jarvis_settings.json` through `core.settings_io` (max_saved_videos, meetings, app_launch_rules, auto_update_enabled, feature_modules), `~/Jarvis_YT_Saved.txt`, `data/game_mode_prefs.json`, Telegram keys in the secrets file (the token never goes back to the UI). Every change answers with the fresh state; links must be http(s), `update_install` exits the process after the reply |
| `modules` | `{op: state\|profile\|module\|reset\|briefing\|restart, ...}` | Settings > Modules (`ui_next/bridge/modules.py`, screen `modules.js`). Storage: `feature_profile`, `feature_modules` (only switches that differ from the profile are stored), `briefing` (include_* flags, calendar reminders; keys of other writers are kept) in `jarvis_settings.json` through `core.settings_io`; flags are refreshed at once. `restart` starts a new copy and exits after the reply |
| `ai` | `{op: state\|provider\|model\|key_save\|key_clear\|local_url\|params\|web_search\|mini_window\|refresh\|test, ...}` | Settings > AI (`bridge/ai.py`): provider and model (a custom model id is allowed), API keys, the local server address, temperature / max tokens / top-k, OpenAI web search, the answer window. A key is written to the secrets file through `actions.mail_client._update_env_var` and **never returned**: `state` only says `has_key` per provider. `refresh` reads the model list from the provider with the stored key; `test` sends one tiny request through `features.qa.llm_processor.ask_llm` and reports the time |
| `backup` | `{op: export\|preview\|apply, ui?, token?}` | Settings backup (`bridge/backup.py`): `export` asks for a file in a native "save as" dialog and writes the settings (no secrets, no machine-bound values), the user's calendar events and the appearance keys sent in `ui`; `preview` asks for a file, validates it and returns a `token`, changing nothing; `apply` {token} restores it after the user confirmed. Paths are never taken from the screen |
| `wizard` | `{op: state\|done\|reset}` | First-run wizard flag (`bridge/wizard.py`): `ui_wizard_done` in the settings; `done` also sets the old window's `first_run_done` |
| `answer` | `{op: close}` | The answer card (`bridge/answer.py`): the user dismissed it. The card itself comes on the sticky `answer` topic `{id, visible, subject, text, image, video}`: `ui/hud_ai_window.py` offers every show / text / image / video / hide to `bridge.answer_event` first, so while the new window is connected the old Tk answer window stays closed |
| `prompt` | `{op: answer, id, status: ok\|cancel, value}` | The answer to a dialog the core is waiting for (`bridge/prompts.py`, kinds built in `bridge/dialogs.py`). The dialog comes on the sticky `prompt` topic `{id, kind, open, data, timeout}` (kinds `text`, `git`, `cleanup`, `yt`, `notice`); spoken confirm / cancel words arrive as non-sticky `prompt_cmd` `{id, action}`. An `ok` value is validated against what was offered: only listed files are staged, only listed paths are deleted, a name cannot contain path separators, a branch name cannot start with a dash or contain `..` |
| `perf` | `{op: watch}` | System screen (`bridge/perf.py`): keeps the collector going for 12 s and returns the last sample. The collector (psutil once a second, PowerShell counters and `nvidia-smi` every 10 s in their own threads, a TCP connect to 1.1.1.1:443 as the delay probe) runs only while a watch is fresh; the screen sends one every 5 s. Samples go out on the non-sticky `perf` topic `{ts, uptime, ping, cpu, ram, disk, net, gpu, hist}` with a 120-second history per series. No CPU temperature on machines without an ACPI thermal zone: the screen says so |
| `dev` | `{op: state\|editors\|ctx_add\|ctx_remove\|parent_search\|depth\|ext_add\|ext_remove\|editor_default\|editor_add\|editor_remove\|project_save\|project_remove\|project_open\|pick_folder\|find, ...}` | Settings > Developer (`bridge/dev.py`): IDE context apps (`context_apps`), parent-folder search and its depth, extensions for new files, editors (found on the PC plus custom `custom:<exe>` ones) and the "get to work" projects (`dev_projects`). Written through `core/settings_io.py`; editors are found and projects started by `actions/dev_projects.py`. `editor_add` and `pick_folder` open native dialogs; a project path must exist, an editor must be a known key |
| `media` | `{op: state\|control, action?: toggle\|play\|pause\|stop\|next\|prev\|seek_to\|seek_by, id?, seconds?}` | What plays on this PC and its controls, through the Windows media sessions (`actions/now_playing.py`); the same sessions are published as the `nowplaying` topic once a second (`{sessions: [...], at}`) |
| `cinema` | `{op: state\|add\|remove\|default\|watch, ...}` | The Cinema screen (`ui_next/bridge/cinema.py`): viewing services stored under `cinema` in `jarvis_settings.json`, and `watch` {title, id?, kind?, season?, episode?} that opens the search page in the browser. Library ops (`actions/media_library.py`): `lib` {force?} (folders, series, movies), `lib_add` {path?} (without a path a native folder dialog opens), `lib_remove` {path}, `lib_play` {path} or {key} (next episode of a series); `info` {title} (status and episode dates from TVmaze, `actions/tv_info.py`), `info_calendar` {title}, `later_add` {title, kind}, `later_remove` {id}, `mode` {on}, `mode_level` {value}; `state` also returns `later` and `mode`; a played path must be a file the scan knows |
| `dialog` | `{name}` from `settings, extensions, mail, songs, deck, perf_monitor, spell_editor, keybind_editor` (still allowed; the System screen and the profile editor replace the last three) | opens that old-HUD dialog through `hud._hud_queue` (rule 4: never from the bridge thread); until a screen exists in the new UI, the nav items Songs, Mail and Settings use it |
| `extension` | `{id, on}` | install / uninstall only for extensions without a setup flow (`bridge/extensions.py: SIMPLE`); others answer `needs_setup` and the UI sends the user to the old dialog |
| `run` | `{id, confirm?}` | runs a catalog command through `handler.handle(id, phrase)` on a worker thread. The phrase comes from the server-side catalog (`try`), never from the UI. `mode: confirm` commands (shutdown, restart, delete, cleanup...) need `confirm: true`; `mode: voice` commands (need an argument or act on the focused window) are refused. |

The game-mode switch uses `run` with `game_mode_on` / `game_mode_off`. `main.py` passes the `CommandHandler` to `bridge.start(handler)`.

Not wired yet (the UI shows an empty state, not fake data): calendar events, mail, songs, guard events. The game-mode toggle is read-only; commands from the UI back to the core are the next step.
