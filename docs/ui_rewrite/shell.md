# Tauri shell behaviour

The shell is `ui_next/shell/src-tauri` (`src/main.rs`). The program is `jarvis-ui.exe`, started by the Python core (`ui_next/shell.py`; from a build it lives in `Jarvis\shell\`). Pages are embedded at build time: rebuild with `cargo build --release` (stop `jarvis-ui.exe` first) after any change in `ui_next/web`. The core can ask it to come forward with the command `show_window` (the page calls it when the core publishes `uicmd show`).

- **Window placement.** Position, size and the maximized flag are saved to `%LOCALAPPDATA%\Jarvis\ui_window.json` when the window is closed to the tray or quit from the tray. On start the saved place is used only if at least the top-left 120x40 px of the window lies on a present monitor; after a monitor was unplugged or the layout changed the window opens at the default size, centred. `JARVIS_SIZE` (tests) skips the restore.
- **Tray.** An icon with the menu "Открыть Jarvis" and "Выход"; a left click opens the window. The close button hides the window to the tray; only the tray menu quits the shell, and then the core exits too (`ui_next/shell.py` watches the process: an exit within 5 s of the start means the launch was forwarded to a window that was already open and is ignored). The core ending closes the shell. The menu texts are Russian only (the shell does not know the interface language).
- **Single instance.** A second launch of the shell shows and focuses the running window and exits.
- **Pop-up window.** Label `popup`, page `popup.html` (`popup.js`, `popup.css`): transparent, no frame, always on top, not in the taskbar, never takes the keyboard focus (`focusable(false)` and a `SW_SHOWNOACTIVATE` show, because a plain `show()` makes it the foreground window). It is created hidden at start. It shows what the assistant tells the user over any program and while the main window is in the tray: the answer card (`answer.js`, the `answer` topic: AI answers, the recognised song with its buttons) and the notices the core waits for (`prompt` topic, kind `notice`: reminders, timers, the camera guard; the buttons answer through the `prompt` command and a spoken "ок" / "отмена" arrives as `prompt_cmd`). The page reports the height of its cards (`ResizeObserver` on the body) to the command `popup_fit`, which sizes the window, puts it in the bottom right corner of the primary monitor's work area and shows it; a height of 0 calls `popup_hide`. The main window does not draw these two any more while it runs in the shell (`window.__TAURI__`); a browser page without the shell still draws them. Blocking questions that need typing (a name, a commit message, the video picker) still bring the main window forward. The colour theme is copied through `localStorage.jarvisHue` (written by `app.html`, read on the `storage` event).
- **Small monitor window.** The "Мини-окно" button on the System screen calls the command `open_perf_mini`, which opens `perfmini.html` (label `perfmini`: 300x232, no frame, transparent, always on top, not in the taskbar). Header buttons: short (190x200, numbers only), transparent background (the header shows on hover), pin on top (on by default), close. The choices are kept in the browser storage (`pmCompact`, `pmGhost`, `pmPin`). The window creation is an `async` command: a synchronous one deadlocks on Windows. The capability file `capabilities/default.json` lists the windows (main, perfmini, popup) and the window permissions the page uses.
- **Not done.** A second physical monitor was not available: the placement logic was checked with a saved position and an off-screen one. The shell has no splash window (the page has its own start animation) and no tray notifications.
